# SB-07 focused ECC Security Review

15 October 2026. Self-review of UI refinements, error presentation and retained room/content boundaries. No independent certification or public penetration test.

- Changes are limited to client presentation, photo keyboard/gesture controls, released-section anchors and test helpers. Section links depend on the already authorized view; they do not fetch future evidence or private content. Country/score guidance adds no new game data. Existing React text interpolation, safe HTTPS provenance links and controlled drawing paths remain intact; no raw HTML insertion was added.
- The server still checks exact origin, cookie identity, room membership and current generation for reads/actions. A neutral fixed photo route checks authorized started-case membership and private/no-store caching. Public assets contain only the client/shared boundary. Existing integration tests exercise unauthorized photo requests, source-file probes, build-import boundaries, private projections and literal markup handling.
- Headers retain nosniff, no-referrer and frame denial. Credentials remain Secure, HttpOnly, SameSite=Strict host cookies. No server logs of cards, ballots, tokens or request payloads were introduced; the entrypoint logs the listening address or a sanitized listen error code. No additional storage, service or analytics exists.
- Existing constraints remain: four seats per room, maximum 128 in-memory rooms, 512 sessions, 2048 rate-limit buckets, 120 socket messages per connection/minute and per game-action/session budget; one-second autosave debounce. Drawings allow at most 128 strokes / 2000 total points on the server; the UI stops at 1900 points. Game actions are capped at 48,000 serialized bytes; Socket.IO frames at 64 KiB. These are ceilings, not a concurrent-load performance claim.
- A new browser check sends an oversized save below the socket transport ceiling, verifies visible rejection/Unsaved, and confirms the prior accepted drawing remains the one published at Gallery. Existing malformed-coordinate/path/point-limit, invalid-caption/reason, late/retry and cross-room tests remain regression gates.
- Lockfile unchanged. Audit returned zero reported vulnerabilities; resolved license inventory and the undeclared-field MIT license were reviewed in THIRD_PARTY.md. This does not guarantee absence of unknown vulnerabilities.

No supported new authorization/disclosure defect was found in the changed code. UI navigation initially lacked keyboard photo panning and direct released-section access; those usability defects were corrected with browser RED/GREEN. Mobile touch scroll/pan/draw separation passes Chromium emulation. A sticky header can overlap elements in a full-page/element screenshot taken after auto-scrolling; viewport screenshots with anchor navigation are used to inspect actual interaction. Screenshots and browser diagnostics are excluded from the distributable source archive.

Residual gates: actual trusted HTTPS access on four devices, physical touch/browser behavior, human 40-second sketch limit fit, human rehearsal and blind study. In-memory restart loss, anonymous-cookie theft risk and unmeasured concurrent capacity remain as previously documented. No deployment or expansion of the prototype security model occurred.
