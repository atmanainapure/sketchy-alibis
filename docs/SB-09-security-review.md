# Private demo scoped ECC Security Review

15 October 2026. Self-review of the current version 8 application, unchanged runtime code in the version 9 source handoff. Target: a private one-room/four-player demo on loopback, with existing TLS support available separately. No external scanning, load attack, infrastructure provisioning or independent certification.

**Finding:** no new functional or security defect blocking this local demo was reproduced. No production code changes or TDD RED/GREEN fix was needed. The new capacity test initially failed typechecking because the approved readonly pack was passed to a mutable fixture parameter; parsing it through the existing case schema fixed test setup. That compile error is not a behavioral RED result.

| Boundary | Inspected implementation and evidence |
| --- | --- |
| Room isolation | `Rooms.membership`, `gameRead`, `gameAct`, `read`, `photo` derive actors from the verified server session, compare the requested room and enforce socket/generation ownership. `publishGame` projects separately per member. Existing rooms/game/photo integration tests reject outsider and cross-room access. New bounded test rejects an additional nonmember's game read. |
| Session ownership | `sessions.ts` hashes a 256-bit opaque token, rejects malformed/duplicate cookie values and enforces expiry. `application.ts` checks exact origin and cookie session on every socket request. Cookie remains Secure, HttpOnly, SameSite=Strict and host-scoped. `Rooms.writable` precedes replay lookup; takeover requires explicit interaction and old tabs lose access. SB-06 replay/revocation/expiry checks pass in the current unit/integration run. |
| Hidden roles and ballots | `CaseAuthority.view` constructs public/self allowlists. The result, all cards and ballots appear only at Solution; evidence at 140s, gallery at 85s. Reconnection uses that same projection. New approved-content seven-phase recovery checks pass; normal-flow real-case privacy and public-bundle checks from SB-07 remain applicable because client/server/content bytes are unchanged. |
| Input and retries | Strict Zod schemas reject unknown fields, invalid countries, self-votes, malformed normalized paths and oversized captions/reasons. Server drawing limits: 128 strokes / 2000 points; UI 1900 points. Game-action byte cap 48,000 and transport cap 64 KiB; exact receipt retries do not duplicate effects. Existing invalid-input/deadline/replay tests pass. Four clients concurrently saved 1900-point drawings for ten rounds without failed acknowledgments or early public disclosure, then auto-locked at Gallery; a late save failed. This is a bounded controlled-clock check, not a hosting benchmark or human sketch-fit test. |
| Secrets and assets | Build guard keeps server content out of client imports; production serves only dist/client; protected file probes pass. Photo uses a fixed allowlisted private asset route. No raw HTML rendering was found in client source. Session storage contains seat/retry/timing metadata, not alibis, ballots or the credential. Log paths print only startup address/sanitized errors. A targeted scan of src/tooling/docs found no private-key, AWS-key or GitHub-token patterns; this is not an exhaustive secret scanner. |
| Dependencies | Manifest/lock unchanged. Fresh `npm audit --json` reports zero vulnerabilities. Exact versions and resolved license inventory remain in THIRD_PARTY.md; dependency package notices are retained by npm installation. No auto-upgrade or audit fix was applied. |
| Local delivery | Build/typecheck and production/HTTPS/WSS smoke checks pass. No remote override for clock, content, roles or approval exists. No deploy-time credential is required for loopback use. Runtime uses one process and in-memory state; no multi-instance or proxy trust assumptions were added. |

Known limitations: possession of a valid anonymous cookie means possession of that seat; there is no account recovery. Room codes are private invitations, not individual identity credentials. Browser storage must work. Cookies on HTTP loopback were verified in Chromium; physical browsers and non-loopback trust were deferred. Restart ends all in-memory rooms. A secure public hosting assessment, cross-browser certification, Internet abuse resilience and measured multi-room capacity remain outside this private-demo handoff. A zero-vulnerability audit is not a security guarantee.
